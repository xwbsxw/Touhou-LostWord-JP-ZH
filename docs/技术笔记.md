# 技术笔记

## 1. 主表（master 数据表）

### 1.1 存储位置与命名

```
/data/data/jp.goodsmile.touhoulostword_android/files/cache/<hash>
```

`<hash>` = `md5(snake_case(表名) + "_master")`，脚本里叫 `table_names.json` 的映射表已收录 212 张。

例：`Mission` → `9b8910ec...`（具体见 `data/table_names.json`）

### 1.2 加密

- 算法：**AES-128-CBC + PKCS7**
- KEY / IV 由 `lw_master.py` 里的 `SECRET` 与固定字符串 `"MasterMsgPack"` 派生
- 解密后是 **msgpack**，结构为 `{行ID: [字段0, 字段1, ...]}`

```python
from lw_master import decrypt, encrypt
raw   = decrypt(open('某表', 'rb').read())      # bytes
obj   = msgpack.unpackb(raw, raw=False, strict_map_key=False)
blob  = msgpack.packb(obj, use_bin_type=True)
enc   = encrypt(blob)                            # 可直接覆盖设备文件
```

### 1.3 汉化流程

1. 从设备导出全部主表到 `dumped/<hash>.msgpack`（已解密）
2. 译文汇总在 `data/trans_all.json`，格式：
   ```json
   { "Mission": { "110610": { "2": "通关「终幕」" } } }
   ```
   即 `表名 → 行ID → 字段序号 → 译文`
3. `python lw_patch.py build data/trans_all.json` → 生成 `out/<表名>.bin`（已加密）
4. `python lw_reapply.py tables` → 推到设备并校验

**只改点名到的字段**，其余字段（类型、顺序、数量）原样保留。

### 1.4 字段语义提醒

很多字段不是给人看的，**翻译会破坏逻辑**：

- JSON 配置（如 `RandomLoginBonus` 的 `{"start_group_id": 1000}`）
- 资源路径（`Graphics/Comic/BG/xxx.png`）
- 枚举值 / 标识符
- `string.Format` 模板（含 `{0}`、`{1:D}` 等）

`lw_semantic_check.py` 就是专门查这些的。

## 2. 剧情 Bundle

### 2.1 存储位置

```
/sdcard/Android/data/jp.goodsmile.touhoulostword_android/files/UnityCache/Shared/<A>/<B>/__data
```

`<A>`/`<B>` 是 32 位十六进制缓存键，与官方补丁的键一致（同一客户端版本下稳定）。

### 2.2 缓存校验机制（关键）

同目录下的 `__info` 决定该缓存是否有效：

```
-1
<epoch>
1
__data
```

- `epoch` 必须**等于** `__data` 的 mtime（秒级）
- `__info` 自身的 mtime 也建议设成同一个 `epoch`
- 不匹配 → 游戏判定缓存失效 → **自动重新下载**

写入方法：

```bash
E=$(stat -c %Y <dir>/__data)
printf -- "-1\n%s\n1\n__data\n" $E > <dir>/__info
touch -d @$E <dir>/__info
```

### 2.3 文本藏在哪

Bundle 内的 `MonoBehaviour`，按脚本类区分：

| 脚本类 | 用途 | 字段 |
|---|---|---|
| `TalkOrder` | 台词主体（**容易漏**） | `m_text` |
| `MessageOrder` | 消息类台词 | `m_text` |
| `SelectOrder` | 玩家「二选一」选项 | `m_strfst` / `m_strsnd` / `m_str3rd` |
| `ButtonOrder` | **玩家应答（点击回复 NPC）** | `m_strbtn` |
| `MessageOrder` / `LoadUnitOrder` / `RenameOrder` | 说话人 / 立绘单位 / 名字变更 | `m_name` |

早期版本只处理了 `MessageOrder`，导致台词大面积缺失；**必须同时处理 `TalkOrder`**。

玩家相关的文字有**两套独立字段**，最易混淆：

- `SelectOrder.m_strfst` / `m_strsnd` / `m_str3rd` —— 二选一的选项
- `ButtonOrder.m_strbtn` —— 点击回复的应答按钮

只翻前者会导致剧情里玩家的回复**几乎全是日文**（主线 361 条里曾漏掉 351 条）。

### 2.4 控制码（务必保留）

| 原字符 | 译文写法 | 含义 |
|---|---|---|
| `\x1bh` | `{P}` | 玩家名占位符 |
| `\x1b` + `mNN`/`fNN` | `{E}` | 表情 / 颜色切换 |

写回前 `restore()`：`{P}`→`\x1bh`，`{E}`→`\x1b`。

写回后**必须**校验：ESC 数量、换行数量与原句完全一致。

## 3. 字体替换

### 3.1 问题

日服字体缺简体字形，直接写简体会显示方块。

### 3.2 方案

Unity 传统字体（`Font`）的 `m_FontData` 字段存放**原始字体文件字节**。把国服客户端使用的方正雅宋 TrueType 数据写进日服的 2 个字体 bundle 即可。

- 日服字体 bundle 键：
  - `8e26f7cd3502423bcaa899485d1ef294 / 6118ba7ff546c9b2fcb0dc64e84547fe`
  - `314db829d8c817469b7b016950eedc3e / 4f7a28726011db3e8c19e2da6e271e53`
- 国服字体：`FZYaSong-B-GBK`，约 10.5 MB，cmap 覆盖 22,002 码位（CJK 20,902）
- `m_CharacterRects = 0`（动态栅格化），所以只换字节即可

### 3.3 生成方法（仓库不含字体文件）

```bash
# 1) 从国服客户端字体包提取 m_FontData
python lw_font_extract.py          # -> lw_work/cn_font_fontdata.bin

# 2) 注入日服两个字体包
python lw_font_inject.py           # -> lw_work/font_out/

# 3) 推送
python lw_bundle_push.py "lw_work\font_out"
```

> 字体为商业字库，请自行从已安装的客户端提取，勿再分发。

## 4. 界面文字（UI）

界面文字在 bundle 的两类组件里：

| 组件 | 字段 | 说明 |
|---|---|---|
| `LocalizeText` | `jpText` | **日服渲染的是这个**（不是 enText / m_Text） |
| 普通 `Text` | `m_Text` | 无语言切换的固定文本 |

改法见 `lw_ui_apply.py`（jpText）与 `lw_ui_text_apply.py`（m_Text）。译文表为 `scripts/lw_ui_sc.py`、`scripts/lw_ui_text_sc.py`。

> ⚠️ 只允许改这两个字段。曾因对其他所有字符串字段做繁转简，破坏 GameObject 名称查找，导致签到界面空白、按钮失效。

## 5. 主表译文来源与优先级

`lw_merge.py` 的合并顺序（后者覆盖前者）：

```
模板套用(trans_tm) < 国服原文(trans_cn_tw) < 国服汉化包(trans_cnpatch)
  < 名词表(trans_names) < 规则(trans_rules) < 人工(trans_manual)
```

- **国服数据可直接对齐**：国服 6.6.0 与日服 1.71.1 同表名、同行ID、同字段顺序
- 对齐时带安全闸门：富文本标签一致、`{n}` 占位符为原文子集、ESC 数量一致，任一不满足就丢弃

## 6. 简繁处理

`lw_cc.py` 提供统一转换器：

- `LW_MODE=sc`（默认）→ 不转换，直接用国服简体
- `LW_MODE=tw` → `s2twp`
- `LW_MODE=t2s` → `t2s`

**教训**：`s2twp → t2s` 往返约 10% 失真（`通过→透過→透过`），所以简体工程应从源头用 `sc`，不要先繁后简。

主表繁改简：`lw_simplify.py`，只对「不含假名且 t2s 有变化」的字段转换（含假名的是日文残留，不能动）。
