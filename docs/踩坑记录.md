# 踩坑记录

真实的翻车与修复过程。**接手前建议读完**，可以省掉大量返工。

---

## 1. 剧情台词大面积缺失：只处理了 `MessageOrder`

**现象**：剧情汉化后大量台词仍是日文。

**原因**：剧情台词主要在 `TalkOrder` 组件，早期只提取/回写了 `MessageOrder`。

**修复**：扫 bundle 内全部 `MonoBehaviour`，按脚本类名同时处理 `TalkOrder` + `MessageOrder`（字段都是 `m_text`）。

**教训**：不要假设只有一种脚本类承载台词；先做全量普查再动手。

---

## 2. 剧情译文逐行错位（最严重的一次）

**现象**：主线 0 推送后，863 条里 155 条与情境完全不符，大量台词串位。

**原因**：手工按「原始行号」把译文挂到对象上。但待译行里混有纯符号行（`！？`、`…………。` 等 5 处，行号 18/188/232/624/798），这些不翻译，于是**后续所有译文整体跳号**，越往后偏得越多。

**修复**：
1. 改为**序号绑定**：只数「含假名的待译行」，编号 1..N，脚本按顺序映射回对象的 `path_id`
2. 写 `lw_story_realign.py`：用「ESC 数量 + 换行数量」做结构指纹，DP 序列对齐，把顺序正确但行号漂移的译文自动绑回原文行

结果：860/863 自动绑对，手补 3 条，最终 ESC/换行差异为 0 才推送。

**教训**：
- 永远按「待译行序号」而不是「原始行号」绑定
- 结构指纹（ESC 数、换行数）是很好的对齐特征
- 分批写入（`ALLOW_PARTIAL=True`）可以在只译了一部分时就推送验证

## 3. `{E}` 占位符未被还原

**现象**：游戏里出现字面文本 `{E}m00`。

**原因**：早期 `restore()` 只还原了 `{P}`，漏了 `{E}`。

**修复**：统一 `restore()`：

```python
def restore(s):
    return s.replace('{P}', '\x1bh').replace('{E}', '\x1b')
```

**教训**：所有占位符必须走同一个还原函数，不要分散处理。

## 4. 对 UI bundle 做「全字段」繁转简 → 签到界面报废

**现象**：签到界面物品列表**空白**，`×` 关闭按钮**点了没反应**。

**原因**：为了繁改简，写了个脚本把 UI bundle 里**每一个字符串字段**都做了 `t2s`：

```python
for k, v in t.items():
    if isinstance(v, str):
        t[k] = T2S.convert(v)     # ← 错误：连 GameObject 名、字体名、事件名都转了
```

UI bundle 里有大量**被代码当查找键**的字符串（GameObject 名称、组件名等）。转换后代码按原名找不到对象 → 列表构建失败 → 按钮没绑上。

**修复**：用原本那套**精准字段**的脚本重新生成（只改 `LocalizeText.jpText` 与 `Text.m_Text`）。

**教训**：动 bundle 前必须明确「哪些字段是给人看的」。宁可少改，不可全改。

## 5. 无 root 时 `lw_reapply.py check` 全是误报

**现象**：明明刚推过，`check` 报告「主表 中文版 0，已被覆盖 86」。

**原因**：`check` 内部用 `su -c md5sum` 读设备文件。**无 root 时 su 不存在**，md5 取到空串，于是每条都判为「不一致」。

**修复**：无 root 时改用 `lw_status_noroot.py`（只核 UnityCache 部分），主表状态标记为「未知」。

**教训**：校验脚本本身也要校验——先确认它真的读到了文件。

---

## 6. 无 root 也能改 bundle 的两个隐藏通道

排查时的关键发现：

1. `__info` 的属组是 `ext_data_rw`、权限 `660`，而 **shell 用户正好在该组** → `__info` 可写；但 `__data` 属组是 `u0_a469`、目录是 `2750`（组只有 r-x）→ `__data` 不可写、不可删。
2. 只要把 `__info` 的 epoch 改成与 `__data` mtime 不一致，游戏就判定缓存失效并**重新下载官方原版**。
3. 重新下载后的文件属组变成 `u0_a469:ext_data_rw`（组可写），**此时 shell 就能直接覆盖 `__data`**。

利用这条链，在完全没有 root 的情况下完成了 78 个 UI bundle 的「还原官方 → 再推正确中文版」。

现成脚本：`lw_invalidate.py` → 启动游戏等重下 → `lw_check_redownload.py` → `lw_push_clean.py`

**教训**：权限问题不要只看「能不能读」，要逐层看目录/文件的属主与位。

## 7. 临时 root 的窗口极其短暂

**现象**：澎湃 OS 4 上临时 root 工具授权后**立刻关机**，重启后 root 消失；`su` 二进制在常见路径都找不到。

**应对**：
- 提前把所有重活做完，root 窗口内只跑**最小动作**（chmod / 少量 cp）
- 用设备端轮询器抢窗：每 150ms 检测 `su -c id`，命中立刻执行脚本
- 把要推送的文件**预先 adb push 到** `/data/local/tmp/`（不需要 root）
- 脚本做成**幂等 + 可续跑**

**教训**：短窗口下不要做大数据量搬运，先改权限/先搬小文件。

---

## 8. 设备重启导致校验结果不可信

**现象**：一次统计报告「主表 86 张全部被重置」，实际是设备在统计过程中重启，`adb shell` 返回 `no devices/emulators found`，被当成 md5 值比较。

**教训**：批量操作前先确认设备在线；对空返回值要显式判断，不要默认当数据。

## 9. `s2twp → t2s` 往返失真

**现象**：先转繁中再转回简体，出现 `通过 → 透过` 这类台湾用词。

**实测**：往返约 **10.2%** 失真。

**修复**：简体工程从源头就不做转换（`LW_MODE=sc`），不要「先繁后简」。

---

## 10. 重复长句的换行数肉眼判断错误

**现象**：`遅い遅い…` 这类重复句，终端显示被自动折行，按视觉行数翻译导致换行数不符。

**修复**：不要靠肉眼。直接打印 `len()` 与 `text.count('\n')` 核对：

```
310: len 8  nl 0  → 单行 4 个「遅い」
361: len 61 nl 1  → 两行各 15 个
```

## 11. 浮点键与占位符手误

翻译 Python 模块时手滑产生的问题：

- 写出 `192.5: '...'` 这类**浮点键**（应为整数序号）
- 把 `{P}` 写成 `{ P }`（带空格）→ 不会被还原成玩家名

**修复**：每次写完都跑一遍「非整数键检查 + `{` 空格检查」。

## 12. `・`（中点）导致假名误报

**现象**：严格检查「是否残留日文」时，人名如 `多蕾米・斯威特` 被判为日文。

**原因**：`・` 是 U+30FB，落在片假名区段 `\u30A0-\u30FF`。

**修复**：判定时排除 `\u30FB`：

```python
KANA_STRICT = re.compile(r'[\u3041-\u3096\u309d-\u309f\u30a1-\u30fa\u30fc-\u30ff]')
```

## 13. ADB 守护进程因临时目录不可写而起不来

**现象**：`adb devices` 报 `cannot open ...\Temp\adb.log: Permission denied`，服务起不来。

**修复**：给 adb 一个可写的 TMP：

```powershell
$tmp="$PWD\adtmp"; New-Item -ItemType Directory -Force -Path $tmp | Out-Null
$env:TMP=$tmp; $env:TEMP=$tmp
```

## 14. 中文乱码

**现象**：脚本文件被写成一堆 `鎶婄晫闈?` 之类的乱码。

**原因**：早期用 `Invoke-WebRequest` 下载脚本，把内容存成了字节数组字符串。

**修复**：
- 下载用 `-OutFile`
- 运行前设 `$env:PYTHONIOENCODING='utf-8'`，并 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`
